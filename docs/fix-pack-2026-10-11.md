# RapidRescue fix pack — 2026-10-11

## Included changes
- Admin > Manage Hospitals now loads accounts whose role is `HOSPITAL_MANAGER` and shows an Assign Manager selector for each hospital.
- Assignment uses the existing authenticated admin endpoint `POST /api/admin/hospitals/{hospitalId}/assign-manager?managerId=...`.
- The assignment endpoint returns only safe hospital/manager fields rather than serializing the `User` entity (which contains a password hash).
- Manage Drivers and Manage Patients show a more actionable message when the backend returns HTTP 403.

## Important runtime steps
1. Stop the currently running backend in IntelliJ and start it again after opening this version.
2. Stop the frontend terminal and run `npm run dev` from `frontend`.
3. Log out of RapidRescue, then log back in using an account whose database role is `ADMIN`; the frontend role label alone is not proof the backend account has that role.
4. Create/register a `HOSPITAL_MANAGER` account if none exists, then open Admin > Manage Hospitals and assign it to a hospital.
5. If Manage Patients/Drivers still returns 403, inspect the browser Network request and confirm the signed-in account's `role` in the backend database is `ADMIN`. Do not remove backend authorization to hide the error.

## Verification status
This fix pack has not been integration-tested against the user's local PostgreSQL database or browser session. The user's local JWT/account role and current database contents cannot be inspected from this archive. Do not treat the presence of the UI as proof the assignment succeeded; verify the success message and manager dashboard after assignment.


## Follow-up patch (manager assignment and admin access diagnostics)
- Added a dedicated Admin-only `/api/admin/managers` endpoint returning active Hospital Manager accounts without password fields.
- Hospital API response now includes assigned manager id/name/email so the assignment is visible after reload.
- Hospital Manager assignment remains protected by the backend Admin role check and validates the manager role.
- Added a safe hospital deactivation action instead of hard deletion, preserving historical emergency references.
- Added driver account deactivation using the existing user active/inactive mechanism.
- Updated Access Denied copy to explain that the frontend can display stale local role data while backend authorization remains authoritative.
- Important: a 403 from `/api/admin/*` is not safely fixed by disabling security; the logged-in database account must actually have the ADMIN role. Sign out/in after changing accounts.

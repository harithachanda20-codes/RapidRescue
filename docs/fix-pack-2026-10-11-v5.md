# RapidRescue focused fix pack — v5

Changes in this checkpoint:
- Hospital manager assignment is transactional and moves a manager's prior assignment to the newly selected hospital, preventing a stale dashboard association.
- The manager endpoint returns a clear 404 message when no hospital is assigned, and loads the safe response inside a read-only transaction.
- Hospital Manager dashboard presents actionable authorization/assignment errors and a manual Refresh control instead of only a generic server message.
- Patient live tracking polls every 2.5 seconds with a 4-second request timeout; overlapping requests remain prevented.
- The standalone patient tracking link is rendered only for PATIENT users; Driver dashboard continues to use its own GPS navigation controls rather than the patient tracking CTA.

Verification: source-level edits only. Full Maven compilation, Vite production build, and live PostgreSQL/API testing must be run on the user's machine before considering this release verified.

## Manual validation checklist
1. Sign in as Admin, assign one active HOSPITAL_MANAGER account to a hospital, and confirm the assigned name/email persists after reloading Manage Hospitals.
2. Sign in as that exact manager email and open `/hospital-manager`; the assigned hospital should load. If the dashboard says no assignment, verify the account email/role and selected manager match.
3. Open a Patient emergency with a tracking token; status/location refresh should poll at 2.5-second intervals, subject to server/network latency and browser scheduling.
4. Driver's GPS navigation controls remain available for driver-side GPS updates; the patient-facing “Track Ambulance Live” link is not rendered for non-patient roles.
